# Atlasware - Controle de Acesso Hierárquico

## Objetivo do Projeto
Implementar um sistema de controle de acesso baseado em:
- **Hierarquia:** Master > Coordenação > Gerentes > Funcionários.
- **Times:** Comercial, Financeiro, RH, etc., com possibilidade de sub-times.
- **Delegação em camadas:** o nível acima define o “limite” de recursos que o nível abaixo pode usar e repassar.

## Conceitos Principais

### Usuário
Representa qualquer colaborador da empresa.
- Tabela: `tb_users`
- Campos principais: `id`, `name`, `email`, `id_lider` (possível uso como líder direto).

### Role (Cargo / Nível)
Define o “peso” do usuário na hierarquia.
- Tabela: `tb_roles`
- Exemplo de roles:
  - `Master`
  - `Gestor`
  - `Colaborador`
  - `Viewer`
- Usado em:
  - `tb_user_roles` (cargos globais do usuário)
  - `tb_user_teams` (cargo do usuário dentro de um time)

### Time
Representa uma área / setor / equipe, com possível hierarquia pai/filho.
- Tabela: `tb_teams`
- Exemplo:
  - `Administrativo`
  - `RH` (filho de `Administrativo`)
  - `Comercial`, `Financeiro`, etc.

### Permissão
Cada “recurso” do sistema que pode ser controlado.
- Tabela: `tb_permissions`
- Exemplo:
  - `ver_relatorios`
  - `editar_usuarios`
  - `aprovar_financeiro`

## Associações Importantes

### Cargos Globais do Usuário
- Tabela: `tb_user_roles`
- Define em qual coluna da visão hierárquica o usuário aparece:
  - `Master`
  - `Coordenação` (ex: role `gestor`)
  - `Gerentes`
  - `Funcionários` (ex: role `colaborador`)

### Membros de Time
- Tabela: `tb_user_teams`
- Define:
  - Em quais times o usuário participa.
  - Qual cargo ele ocupa **naquele time** (gestor, colaborador, etc).

### Pacotes de Permissões por Time
- Tabela: `tb_team_permissions`
- Define quais permissões pertencem a um determinado time.
- Pode ter um campo `allowed_till_role_id` indicando até qual nível hierárquico essas permissões podem descer.

## Visão de Acesso (4 colunas)

Tela `/admin/access` mostra:

- Coluna **Master** → usuários com role `Master` / `admin`.
- Coluna **Coordenação** → usuários com role `gestor`.
- Coluna **Gerentes** → (futuro) usuários com role `gerente`.
- Coluna **Funcionários** → usuários com role `colaborador`.

Em cada card de usuário, são exibidos os times em que ele atua e o papel em cada time.

## Fluxo Geral (alto nível)

1. **Admin/Master**:
   - Cadastra roles, times, permissões.
   - Define pacotes de permissões por time (`tb_team_permissions`).

2. **Gestores de time**:
   - Via `tb_user_teams`, são marcados como responsáveis por times.
   - Podem gerir membros do time e, no futuro, delegar parte dos recursos para subordinados.

3. **Funcionários**:
   - Recebem permissões conforme:
     - seus times,
     - seu cargo no time,
     - e as regras de delegação definidas acima.
